# TentaOS 验收文档(QA)— Phase 1→20

> 每个 Phase 做完,按这里的步骤验收。**全绿才进下一个 Phase。** 与前后端文档按编号对齐。
> 通用回归(每个 Phase 都要顺带确认):① Engine 连接指示器为绿;② 提交一个简单任务仍能跑通;③ `npm run build` 通过;④ 刷新页面状态能恢复。

记号:☐ 待测 / ✅ 通过 / ❌ 失败(记录现象)

---

## Phase 1 — 数据模型
- ☐ `src/types/pipeline.ts` 存在,导出全部契约类型,build 通过
- ☐ `derivePipeline(mockTask)` 单测:输入 mock JSON,输出 Pipeline 结构字段齐全
- ☐ `pipelineStatus.js` 被 TaskCard 引用(无重复定义)
- 期望:无 UI 变化,纯地基

## Phase 2 — Command Bar
- ☐ 进入应用看到大输入框 + placeholder 示例
- ☐ 输入框下方有 3 个示例任务,点击后文本填入输入框
- ☐ 提交合法任务 → loading → 成功 toast → 跳 Run View
- ☐ **断开 Engine 后提交 → 出现红色 toast(不静默,不卡住)**
- ☐ 空输入不能提交

## Phase 3 — Plan Preview
- ☐ 提交意图 → 看到步骤列表(非空)
- ☐ 每步显示:序号 · 标题 · 工具图标 · 风险标签 · 验证判据文案
- ☐ high-risk 步骤有明显标记(红边/"需审批"角标)
- ☐ 能删除一步、跳过一步
- ☐ 点 Launch → 进入 Run View 且执行的就是预览里的步骤
- ☐ 后端未就绪时:回退为直接执行,但 step 仍带 risk/verification 字段

## Phase 4 — Run View 实时
- ☐ 提交任务 → 顶部状态条显示标题/状态/进度/Stop
- ☐ 步骤逐个 running → completed,当前步自动滚入视野
- ☐ 终端输出实时追加到对应步骤
- ☐ 浏览器截图实时出现
- ☐ **执行中刷新页面 → 状态正确恢复(靠 GET /api/task/:id)**
- ☐ 点 Stop → 任务停止

## Phase 5 — 证据面板
- ☐ 右侧有 截图/终端/diff 三区
- ☐ 运行中截图、终端实时更新
- ☐ 完成后点任意步骤 → 面板切到该步证据
- ☐ diff 区显示改了哪些文件、+/- 行
- ☐ diff 不暴露工作区外路径

## Phase 6 — 验证摘要
- ☐ 每步完成显示 ✓/✗ + 验证判据(如 "✓ npm test passed")
- ☐ 完成时顶部出现验证摘要卡(哪些 check 过、最终 diff、耗时、成本)
- ☐ **构造一个会失败的验证 → 该步显示红 ✗ 且整任务不显示绿色"完成"**
- ☐ 验证未跑的步骤显示"待验证"而非"完成"

## Phase 7 — Runs 列表 + Replay
- ☐ 列表显示任务,状态筛选 tab 工作正常
- ☐ 进行中任务卡片实时更新
- ☐ 无任务时显示教学空状态 + 跳转按钮
- ☐ 点历史任务 → replay 模式,可点步骤逐个看当时证据
- ☐ 刷新后历史仍在

## Phase 8 — Approvals
- ☐ 触发 high-risk 操作 → 任务停在 awaiting_approval
- ☐ Run View 行内出现审批卡片,含 要做什么/风险原因/**预期影响(文件+命令)**
- ☐ 批准 → 继续;拒绝(带理由)→ 停止
- ☐ low-risk 步骤显示 "auto-approved"
- ☐ 有待审批时导航 Approvals 红点亮起
- ☐ 独立 Approvals 队列页能看到并处理

## Phase 9 — 检查点 + 回滚
- ☐ 每步完成出现"检查点"锚点
- ☐ 急停按钮带确认,点后任务干净停止
- ☐ 点某检查点的 Rollback → 确认 → 工作区/状态回退到该点
- ☐ **回滚后用 GET /api/task/:id 核对状态确实回退**
- ☐ 回滚失败时有明确报错,不留半状态

## Phase 10 — 偏好 + 模板
- ☐ Settings 能设执行偏好(如"部署前必跑测试")
- ☐ 设了偏好后,新任务的计划里出现对应验证步骤(偏好生效)
- ☐ PlanPreview 能"存为模板"
- ☐ Command Bar 能"从模板开始",载入模板步骤

## Phase 11 — Fork 钩子
- ☐ task 带 forks 字段时不报错
- ☐ 无 forks 时行为与之前完全一致(回归)

## Phase 12 — Fork 泳道
- ☐ 一个意图发起 fork → 看到 2-3 条并排泳道
- ☐ 各泳道按 fork_id 正确显示各自步骤,互不串
- ☐ 各 fork 在隔离环境执行(后端确认文件互不影响)
- ☐ 并行执行不卡死、不互相拖累

## Phase 13 — 记分卡
- ☐ 各泳道跑完显示验证记分卡(列出 check 结果)
- ☐ 每 fork 有综合 score
- ☐ 最高分 fork 被高亮
- ☐ **核对 score 来自客观 check,不是模型自评**

## Phase 14 — 合并 + 存档
- ☐ 获胜 fork 有 Merge 按钮
- ☐ high-risk 合并弹人工确认,不能跳过
- ☐ 合并 → 看到合并后的最终 diff
- ☐ 后端确认落败 fork 已入库为反事实数据
- ☐ **合并可回滚:合并后用 P9 回滚能恢复主项目**

## Phase 15 — 时间线
- ☐ 完成任务有横向事件时间线
- ☐ 节点含 step/审批/检查点/fork 分叉/合并,点击跳证据
- ☐ replay 可拖游标回看任意时刻

## Phase 16 — 指标面板
- ☐ Metrics 页显示成功率/延迟/成本/fork 胜率趋势图
- ☐ 切换时间范围数据更新
- ☐ 数据与实际任务记录一致(抽查一两条)

## Phase 17 — 安全
- ☐ 任务在受限权限下执行;越权(访问工作区外/未授权网络)被拒绝并记录
- ☐ 密钥不出现在终端输出、diff、日志、证据里(全程搜一遍)
- ☐ 超资源限额的任务被终止

## Phase 18 — 可靠性
- ☐ 长测套件能跑通,产出成功率/超时/重试指标
- ☐ 压力下检查点/回滚仍正确(随机回滚抽测)
- ☐ 指标进入 Metrics 页

## Phase 19 — 多用户
- ☐ 注册/登录/登出正常,token 过期能刷新
- ☐ 两个账户数据严格隔离(A 看不到 B 的任务/偏好/模板)
- ☐ 同账户跨设备登录看到一致数据
- ☐ localStorage 数据成功迁移,有回退

## Phase 20 — Billing
- ☐ 用量被准确计量(跑几个任务核对计数)
- ☐ 套餐门槛生效(超额拦截/降级)
- ☐ 超额时 Command Bar 友好提示并引导升级
- ☐ 与 Creem 流水对账一致

## Demo 就绪线(给投资人前必须全绿)
完成 **Phase 1-9** 即具备一条可演示的完整闭环:
> 输入意图 → 看带风险/验证的计划 → 启动 → 实时看证据 → high-risk 处审批 → 完成时看验证摘要 → 可急停/回滚 → 历史可回放。

完成 **Phase 12-14** 即具备**差异化高光**:并行多个可验证的未来 → 客观择优 → 安全合并。

建议 demo 录屏脚本:跑一个真实开发任务,故意触发一次审批,展示验证摘要与最终 diff;再展示一次 fork 对比择优合并。全程强调"每一步都有证据"。
